# Agent 工作规范

本文件定义本仓库内所有 Agent / AI coding assistant 必须遵守的开发流程、设计原则、代码修改原则、测试和文档要求。

## 1. 开发流程要求

### 1.1 开发前必须完成

每次开始开发任务前，必须先输出：

- 需求理解
- 影响范围分析
- 详细实现计划
- 风险点分析
- 验收标准

未经计划确认，不允许直接开始编码。

### 1.2 开发阶段要求

每完成一个明确阶段，必须执行：

- 本地 Git Commit
- 更新开发日志
- 更新 next-steps 文件
- 总结当前完成情况

禁止多个阶段完成后一次性补日志。

### 1.3 开发结束要求

每个阶段结束必须输出：

- 已完成内容
- 未完成内容
- 已知问题
- 下一步计划
- 涉及文件列表

## 2. 设计原则

### 2.1 禁止过度设计

禁止为了未来可能存在的需求：

- 提前抽象
- 提前扩展
- 提前插件化
- 提前微服务化

遵循：

- 当前需求 + 可预见一到两次迭代即可。

### 2.2 禁止极简设计

禁止：

- 所有逻辑堆在一个类
- 所有逻辑堆在一个方法
- 缺少必要抽象
- 缺少必要模型

要求：

- 保持合理分层
- 保持职责单一
- 保持可维护性

### 2.3 优先遵循现有项目结构

新增代码时，优先遵循：

- 现有目录结构
- 现有命名规则
- 现有架构风格
- 现有异常处理方式

禁止重新发明框架。

## 3. 代码修改原则

### 3.1 最小修改原则

仅修改当前需求相关代码。

禁止：

- 顺手重构
- 顺手优化
- 顺手格式化大量文件
- 修改无关代码

### 3.2 保持兼容性

涉及以下内容时，必须评估兼容性：

- API
- 数据库
- 配置文件
- 消息结构

如存在破坏性变更，必须明确标注。

### 3.3 数据库修改要求

所有数据库变更必须提供：

- Migration
- Upgrade Script
- Rollback Script

并记录到开发日志。

## 4. 注释要求

### 4.1 必须编写注释

重点说明：

- 为什么这样做
- 特殊业务规则
- 边界条件

### 4.2 禁止无意义注释

禁止解释代码表面含义，例如：

```csharp
// 创建对象
var user = new User();
```

## 5. 测试要求

### 5.1 新功能

必须提供：

- 单元测试
- 或明确无法编写原因

### 5.2 Bug 修复

必须补充：

- 复现测试
- 修复验证

避免问题再次出现。

## 6. 文档要求

### 6.1 开发日志

持续维护：

- `development-log.md`

记录：

- 需求
- 需求变更
- 决策记录
- 实现过程
- 问题记录

### 6.2 下一步计划

持续维护：

- `next-steps.md`

要求：

- 可执行
- 可验证
- 按优先级排序

## 7. Agent 模型使用规范

### 高级模型（5.5 High）

用于：

- 架构设计
- 需求分析
- 技术方案
- 复杂 Bug 分析
- 数据库设计
- 并发问题分析

### 中级模型（5.3 Mid）

用于：

- 普通编码
- 单元测试
- CRUD 开发
- 文档整理
- 简单重构

### 禁止

禁止使用低级模型处理：

- 架构设计
- 数据迁移
- 安全逻辑
- 并发逻辑
- 核心业务逻辑

## 8. 输出要求

每次任务结束必须输出：

```text
本次完成

...

修改文件

...

风险

...

下一步

...

是否建议提交

YES / NO
```
