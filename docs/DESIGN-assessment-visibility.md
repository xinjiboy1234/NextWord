# DESIGN — 测评记录可视化 + AI 评价展示 + 人话水平评估标准

> 顾言，2026-08-08（I8）。来源：用户体验反馈第 5 条——「测评记录我想要可视化，AI 评价也要展示，我想知道目前到底是什么水平：粗糙、凑合、还不错、用词不当、表达过于简洁等，要纳入评估标准」。
> 愿景锚点：VISION-expression-first——固定等级/分数只是外壳，**详细的画像与评价才是内核**。本设计把「人话评价」从瓶颈洞察（仅服务端）扩展到测评主链路。

## 1. 现状与问题

- 测评数据其实在库里：`GET /api/assessment/{id}` 已返回完整 Records（题目、作答原文、每题四维分、ErrorTags、最终 Dimensions），但**没有按用户列测评的列表端点**，前端也没有任何调用——用户测完就再也看不到了。
- 测评结果页只显示等级 + 综合分 + 后端模板 Comments（数字罗列），**四维分、逐题得分、逐题 AI 评语、TopErrorTags 全不展示**。
- 逐题 AI 评语（`AiRevision`/`Suggestion`）落在 `SentenceLog`（Scene=assessment），但与 AssessmentRecord 无关联；`BlockScores.ProductionScore` 只存四维分 + errorTags，**评语在测评上下文被丢弃**。
- 全代码库没有任何人话水平描述（rubric）：四维 0-5 无分档语义，CEFR 只有通用官话描述。最接近的现成人话资源是瓶颈洞察 7 类 nature 与 `NATURE_META`。

## 2. 需求

- **R1 测评历史列表**：用户能看到自己历次测评（时间、定级、表达综合分、是否触发识别矫正），入口放 /profile 与 /manage。
- **R2 测评详情 + AI 评价**：点开任意一次测评，按块按题看到——题目、自己的作答原文、四维分、总评档、AI 评语与改写建议、错误标签。练习流已有的 `ScoreCard`/`ErrorAnalysis`/`AiRevision` 组件直接复用。
- **R3 人话水平评估标准（rubric）**：建立规则化文案层（零 LLM，成本纪律），把分数翻译成用户能懂的水平描述，展示在测评结果页、测评详情、评估报告头部。

## 3. 方案

### 3.1 人话 rubric（R3，规则映射，零 LLM）

**总体水平标签**：按表达综合分经 `ScoreMapping:CefrBands` 分带后映射（单一数据源，不新增分带副本）：

| 带 | 人话标签 | 一句话描述（示例，实现时可微调） |
|---|---|---|
| A1 | 起步 | 能蹦出单词和简单短句，离成段表达还有距离 |
| A2 | 粗糙 | 能表达基本意思，但错误较多、句式单一 |
| B1 | 凑合 | 日常简单表达能应付，复杂一点就吃力 |
| B2 | 还不错 | 表达清楚连贯，偶有用词不当和不自然 |
| C1 | 很溜 | 表达自然丰富，接近母语者的灵活度 |

**四维特征描述**：grammar/natural/vocabulary/relevance 各按 0–5 分三档映射人话短句：

| 维度 | ≤2（弱） | 3（中） | ≥4（强） |
|---|---|---|---|
| 语法 | 句子结构常出错，时态单复数混乱 | 大结构正确，小错不断 | 稳定正确，能驾驭复合句 |
| 自然度 | 中式表达明显，句子生硬 | 能看懂但不像地道说法 | 表达自然地道 |
| 词汇 | 用词单调重复，有用词不当 | 日常词够用但笼统 | 用词准确有层次 |
| 相关度 | 表达过于简洁或答非所问 | 切题但内容偏单薄 | 切题且言之有物 |

**错误标签人话化**：`TopErrorTags` 在结果页/详情页带中文标签展示（复用/扩展既有错误标签中文映射）。

落点：Domain 新增纯函数（如 `ProficiencyRubric`：分数/带 → 标签与描述），结果页 Comments、测评详情、评估报告 summary 头部统一调用；文案常量集中一处，便于迭代措辞。

### 3.2 测评历史端点（R1）

- 新增 `GET /api/assessments`：当前用户测评列表（id、Type、StartAt/EndAt、FinalLevel、表达综合分、是否矫正 `OriginalLevelBeforeGuard` 非空），按时间倒序；只读、无分页（个人测评次数量级小，顶天几十条）。
- 详情复用既有 `GET /api/assessment/{id}`（数据已全），补一个归属校验确认只能看自己的（若没有则补上）。

### 3.3 逐题 AI 评语存储演进（R2）

- `BlockScores.ProductionScore` 新增可空字段 `Suggestion`/`AiRevision`（JSON 反序列化对旧记录天然为 null）——**新测评起**评语随测评记录持久化，不再依赖 SentenceLog 时间窗关联（脆弱，不做）。
- 旧记录降级：无评语字段时前端只显示四维分 + 错误标签，不报错。
- `SentenceLog` 留痕链路不动（画像/瓶颈证据引用不受影响）。

### 3.4 前端

- 测评结果页：补四维分（含人话特征描述）、总体人话标签、TopErrorTags 中文标签；结论先行、分数靠后（外壳不喧宾夺主）。
- 新页面 `/assessments`（测评记录）：列表 + 详情（按块按题：题目/作答/四维分/评语/改写/错误标签，复用 ScoreCard 等组件）；/profile LevelPanel 等级历史区与 /manage 测评卡片加入口。
- 空态：只测过一次时列表仍可用，文案引导「定期重测追踪进步」。

## 4. 验收标准

1. 完成一次测评后，`GET /api/assessments` 列出该次测评；详情页能看到每块每题的题目、作答、四维分、AI 评语与改写（新测评）；旧测评详情无评语时优雅降级。
2. rubric 映射有纯函数单测：五个分带 → 五个标签；四维各档（≤2/3/≥4）→ 对应描述；边界值（分带交界）断言。
3. 测评结果页与报告头部展示总体人话标签 + 四维特征描述；文案中不出现内部字段名/英文 key。
4. 他人测评 id 访问被拒（404/403）；列表只含本人测评。
5. `dotnet test` 全绿 + `npm run build` 通过；新端点有集成测试（至少覆盖列表归属过滤）。

## 5. 非目标

- 不改测评出题、定级、防伪闸逻辑；不改 Score 写入口径。
- 不做测评分数趋势图（月度时间轴已有 Score 趋势，测评次数太少画图无意义，列表足够）。
- 不做历史 SentenceLog 反向关联补评语。
