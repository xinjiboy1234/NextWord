# 设计方案：「我的这个月」月度时间轴页（T-031）

> 状态：已定稿（2026-07-30，顾言）
> 依据：report/sim-month/REPORT.md 发现一/八（等级历史 30 天一行、坚持一个月看不到曲线）
> 前置：T-022 练习回写（有真实分数变化可展示）、T-026 毕业时刻（设计）、scores/history API 已有未接

## 1. 问题

用户坚持学习一个月，产品能展示的只有一条静态等级和三个数字。Score 快照、学习日志、毕业事件、洞察历史都在库里躺着，没有一处让用户看到「我这个月走了多远」。愿景说「固定分数只是外壳、画像是内核」——目前 UI 连外壳的变化都没展示。

## 2. 方案（顾言拍板）：`/profile` 增加「我的这个月」区块（先不做独立页面）

从上到下一屏内四段，全部消费既有只读数据：

1. **分数趋势图**：`GET /api/profile/scores/history?days=30` 画三维折线（轻量 SVG 自绘，不引图表库）；首月数据不足 7 天时显示「坚持 7 天后出曲线」；
2. **本月里程碑**：时间轴列出本月事件——词毕业（spontaneous_use，含词与日期）、首次通过挑战、定级/升级、画像生成。来源：UserWordRelationships（GraduatedFreeExpressionLogId 非空 + StageUpdatedAt 本月）、ChallengeRecords、LevelHistories、WeaknessProfiles，聚合在一个新只读端点 `GET /api/profile/monthly-timeline?days=30`（后端简单查询拼装，无 LLM）；
3. **画像变化**：当前 WeaknessProfile 的 Finding 与上一份对比——新增的强项、好转的弱点一句话列出（规则 diff，零 LLM）；只有一份画像时显示当前 Finding 摘要；
4. **洞察回放**：最近 3 条 BottleneckInsight（性质中文名 + 结论 + 时间），复用 `GET /api/insights/bottleneck/latest` 的展示组件思路，后端补一个 list 端点或直接并入 monthly-timeline 响应（取实现简单者）。

## 3. 约束

- 前端为主，后端只加一个只读聚合端点；不写任何状态；
- 空数据态每段都要有（新用户看到「坚持 7 天后出曲线」「还没有里程碑，去完成今天的练习吧」）而不是空白；
- 不引新依赖（图表自绘 SVG）；
- 「分数是外壳」的纪律：趋势图视觉权重 ≤ 里程碑与画像变化，页面标题与引导语强调「你会用的词越来越多」而非「你涨了多少分」。

## 4. 验收标准

1. 有 30 天数据的用户（仿真库小菜账号）四段全部有内容且与库内数据一致：分数曲线有起伏（T-022 后）、里程碑含毕业词与挑战通过、画像变化有对比、洞察有回放；
2. 新注册空数据用户四段空态文案正常，无报错无白屏；
3. monthly-timeline 端点只读、无 N+1（单测或日志断言查询数）；
4. npm build 通过，移动端窄屏不横向溢出。
