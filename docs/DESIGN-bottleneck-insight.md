# 设计方案：瓶颈性质洞察 + 重规划触发（T-007）

> 状态：已定稿（2026-07-25，顾言）
> 依据：VISION-expression-first.md §5.1 / §6-5
> 前置：T-005 画像、T-006 PlannerWorker（含周级重规划缺口：无测评的存量用户不会自动获得新 Plan）

## 1. 定位

愿景闭环的最后一环（§6-5）：指标筛查提示异常或平台期 → Agent **细读近期产出原文**判断瓶颈性质 → 触发重规划。「质变」不是水平跃迁，而是瓶颈**性质**的变化（从「词汇量不足」转为「会词但组织不成句」，从「语法错误多」转为「语法正确但表达单调」）——洞察不能只看聚合指标，必须贴近真实产出字里行间地细读（§5.1）。

## 2. 三层机制（顾言拍板）

### 2.1 指标筛查（规则引擎，无 LLM，日级）

随日快照任务运行，识别以下触发信号（满足其一即触发）：

| 信号 | 判定口径 |
|---|---|
| 平台期 | 近 10 次产出四维均分无显著提升（斜率≈0 且波动小于阈值），且期间有持续活跃 |
| 回避模式 | 产出中从句/复杂连接使用率在≥10 次样本内持续走低（指标不差但能力范围收缩） |
| 安全词策略 | Plan 造句目标词在用户自由产出中出现率为 0（新学内容从不进入产出） |

规则只做「要不要细看」，**不做结论**；不触发时零 LLM 成本。

### 2.2 瓶颈洞察（LLM Agent，事件驱动）

触发后，InsightAgent 取近期产出**原文**（SentenceLogs 文本，不只是分数）细读，产出 `BottleneckInsight` 持久化：

- 瓶颈性质分类：词汇量不足 / 会词但组织不成句 / 语法错误多 / 语法正确但表达单调 / 回避模式 / 中式搭配 / 安全词策略；
- 每条判断带证据引用（产出原文 SentenceLog id）——沿用画像的证据纪律；
- 与当前生效 Plan 的主攻方向比对：性质未变 → 仅记录；**性质已变 → 触发重规划**。

### 2.3 重规划（两条路径）

1. **事件驱动**：瓶颈性质变化 → 重新生成画像（Profiler）→ Planner 出新 Plan；
2. **每周兜底**：所有活跃存量用户每周强制重跑一次 Planner（无触发也跑）——补齐 T-006 留下的「无测评用户不获新 Plan」缺口。

## 3. 约束

- 规则引擎分数权威不动：洞察只影响解读与规划，不改任何分数（§5 关键设计约束）；
- 成本：筛查零 LLM；洞察仅触发时一次调用；兜底重规划周级（§2-6、§5 验证与规划只在日/周周期运行）。

## 4. 验收标准（给周密）

1. 指标筛查三类信号各有测试覆盖：构造对应数据能触发、正常数据不误触发；
2. 触发后 InsightAgent 细读产出原文，BottleneckInsight 持久化且带 SentenceLog 证据引用；
3. 瓶颈性质变化 → 自动重规划：新 Plan 生成且主攻方向随洞察调整（对比旧 Plan）；性质未变 → 只记录不重规划；
4. 每周兜底重规划生效：无测评、无触发的存量用户获得新 Plan；
5. 未触发用户全程无 LLM 调用（可从日志/计数验证）；
6. `dotnet test`、`npm run build` 通过。

## 5. 非目标

- 瓶颈洞察的用户可见展示（先服务重规划，展示后续迭代）；
- 多瓶颈并存的优先级排序（取最主要的性质即可，留给迭代打磨）。
