# 设计方案：词生命周期提速——编排向「待推进老词」倾斜（T-026）

> 状态：已定稿（2026-07-30，顾言）
> 依据：report/sim-month/REPORT.md 发现五（一个月 185 词仅 PromptedUse 1、毕业 0）
> 前置：T-014 四阶段生命周期（DESIGN-word-lifecycle.md）、T-023 定级校准、T-027 评分公平性

## 1. 问题

毕业标准「能用」本身是对的，但编排解了它的锁：

- **回忆考察曝光不足**：认识→回忆靠 SM-2 成熟（RepeatCount≥2），回忆→造句使用靠「回忆模式考察通过」。但每日词队列以新词为主，老词成熟后很少再被抽到，仿真一个月只有 11 个词进 Recalled、1 个进 PromptedUse；
- **候选池补位断档**：Planner 造句目标优先取 prompted_use 未确认词，池空时直接落回当日带内新词——老词永远轮不到产出机会；
- **毕业不可见**：就算有词毕业，用户也感知不到（无里程碑反馈）。

叠加效应：用户学一个月，没有任何一个词让他体验「这个词我能用了」。

## 2. 方案（顾言拍板）：不改毕业标准，改编排节奏

### 2.1 每日词队列保证回忆考察位

`GET /api/words/daily` 队列结构：到期复习词优先（SM-2 既有）之外，**每天至少 40% 的名额给「已成熟待回忆考察」的词**（recognized 且 RepeatCount≥2，recall 模式），不足时新词补位；新词占比相应收敛。与 T-006 Plan 词队列共存：Plan 队列词同样按此比例混合考察模式（Plan 决定学什么词，本方案决定考察模式配额）。

### 2.2 造句目标二级补位：Recalled 池

Planner 造句目标选词顺序改为：prompted_use 未确认候选池（既有优先）→ **Recalled 池（recalled 且带内、utility 非 low，按 StageUpdatedAt 最早优先）** → 当日带内词（兜底）。Recalled 词被编入造句目标后，若当日背词队列出现该词则以 recall 模式考察（已天然满足：recalled 词考察模式即 recall）；造句中正确使用仍按既有规则确认（A/B 档 + 词边界命中）。

### 2.3 毕业时刻可见

- 词进 spontaneous_use 当次，自由表达评分响应带 `graduatedWords` 列表，前端弹出毕业提示（「🎉『xxx』毕业了——你已经在自发使用它」）；
- Dashboard 今日学习计划卡下方加一行本周毕业计数（无则不显示）；
- `/review` 与 `/word-bank` 已有阶段派生 MasteryScore=100，补一个「已毕业」筛选/标记（前端纯增量）。

### 2.4 目标口径（验收锚点）

正常活跃用户（每天 10 词 + 3 造句 + 隔天自由表达）**14 天内毕业第一个词**；30 天仿真毕业数 ≥3。

## 3. 约束

- 毕业标准一字不动：词边界命中 + A/B 档 + 自发使用，四阶段状态机不回改；
- 接触词编排规则不受影响（接触词仍只进识别队列）；
- 回忆考察位比例（40%）留常量，后续按仿真数据再校准。

## 4. 验收标准

1. 队列配额单测：构造 10 个成熟 recognized 词 + 新词若干，每日词 recall 模式占比 ≥40%；成熟词不足时自动新词补位不报错；
2. Planner 补位单测：prompted_use 池空时造句目标取 Recalled 池最早词；两级都空才落回带内词；
3. 毕业提示：自由表达触发毕业时响应带 graduatedWords，前端有提示（E2E 或组件级验证）；
4. 仿真验收（周密）：30 天菜鸟剧本重跑，PromptedUse 数量显著上升、毕业数 ≥3、14 天内出现首个毕业词；
5. 既有 T-014 生命周期测试全部保持绿色（状态机行为零回归）。
