# 设计方案：测评重构 — 产出型为主 + LLM 真实评分（T-004）

> 状态：已定稿（2026-07-23，顾言）
> 依据：VISION-expression-first.md §4.1 / §4.2 / §6-2；I1 已交付场景标注词库
> 后续：程实实现（T-004），顺带修 T-008 词表数据质量；周密验证

## 1. 问题（现状测评为什么不行）

| 缺陷 | 位置 |
|---|---|
| 词汇题全库随机、不分难度 | `AssessmentService.cs:241-262` |
| 阅读题硬编码、正确答案恒为 index 0 | `AssessmentService.cs:282-297` |
| 造句评分用词数启发式，非真实评分 | `AssessmentService.cs:333-346` |
| 固定阈值表定级、最短板 min：识别分低会拖低表达好的用户 | `AssessmentScoringService.cs:12-28, 62-74` |

对「练表达」的目标，这是入口定级的系统性误差（VISION §4.1/§4.2）。

## 2. 设计决策（顾言拍板）

### 2.1 任务结构：产出型为主，识别型降级为参考

- **产出型（主，占题量 ≥60%）**：
  1. **提示造句**：给出目标词（水平带内、utility=high/medium）造句；
  2. **情境表达**：给一个生活场景（用 I1 taxonomy，如「点餐时菜品上错了」）写 2–3 句应对；
- **识别型（参考，不计入主定级）**：词义选择 + 阅读理解，只作为参考信号展示。

### 2.2 评分：LLM 真实评分，表达力综合分作主叙事

- 产出题全部走 **LLM 真实评分**，复用造句工作室的四维评分链路（`SentenceLlmScoringWorker` 模式）；Mock 环境走 Mock 评分；
- 定级主叙事改为**表达力综合分**（产出维度加权），识别分仅作参考展示——**废弃最短板 min**；
- 固定等级/分数仍作为给用户看的外壳保留；内核同时记录可读的维度评价，为 I2 后续 WeaknessProfile（T-005）供数。

### 2.3 分块自适应

- 测评按难度带分块进行：以当前估计水平为起点出题，表现好升带、表现差降带，2–3 块内收敛；
- 题目难度参数用 `IntrinsicScore`；每块 3–5 题，总量控制在 15 题以内（测评不是马拉松）。

### 2.4 测评词池纪律（衔接 I1 词库）

- 出题词只选**水平带内**且 `utility=high/medium` 的词；
- **接触词不进测评**：超当前水平带的词一律不出（接触词是背词队列的运行时概念，测评选词按难度带过滤即可）；
- 阅读题改为**从库内文章生成**（按难度选文），正确答案位置随机——废除硬编码与 index-0 恒定。

## 3. 非目标（本轮不做）

- WeaknessProfile 结构化画像（T-005，下一轮）；
- 测评 UI 改版（前端只作最小适配，能跑通新流程即可）；
- 历史测评数据迁移。

## 4. 验收标准（给周密）

1. 产出题占比 ≥60%，识别题结果不计入主定级、仅展示为参考；
2. 产出题评分全部走 LLM 真实评分链路（非词数启发式）；
3. 自适应生效：模拟强/弱两类用户，题目难度带随表现分支，且 15 题内收敛出定级；
4. 测评出题池：无超水平带词、无 utility=low 词；阅读题来自库内文章、正确答案位置不恒定；
5. 主定级由表达力综合分决定，不存在「识别分低拖低整体」;
6. `dotnet test` 通过、`npm run build` 通过；T-008 三项数据质量问题修复（例句字段统一、音标补全、2 个标注错例修正）。

## 5. 成本

测评是低频入口动作（每用户偶发），LLM 评分逐题调用成本可忽略，符合 VISION §2-6。
