# 设计方案：WeaknessProfile v1 + Verifier（T-005）

> 状态：已定稿（2026-07-24，顾言）
> 依据：VISION-expression-first.md §5（①②）/ §6-3；next-steps「评估报告 LLM 结构化叙事」并入本方案
> 输入已就位：I1 场景词库、I2 测评四维评分与错误标签留痕（SentenceLogs / FinalLevel 记录）

## 1. 定位

愿景核心物：**固定等级只是外壳，带证据的详细画像才是内核**。本任务把评估报告从「模板文案」升级为「带证据引用的结构化画像」并持久化，同时引入 Verifier 做交叉验证——不是一个 Agent 说了算（VISION §2-2）。

## 2. WeaknessProfile 结构（顾言拍板）

画像 = 若干条**结论（Finding）**，每条 Finding 五要素：

| 要素 | 说明 |
|---|---|
| 维度 | 场景（taxonomy 子场景，如 dining_out）/ 技能（语法、词汇、自然度、相关性）/ 阅读 |
| 强弱 | strength / weakness / neutral |
| 结论 | 一句可读的话（如「点餐场景核心动词掌握弱，check/order 类词造句错误率高」） |
| 证据引用 | 指向真实数据的引用列表：SentenceLog id、测评题记录、词掌握度统计（场景词覆盖率/正确率） |
| 置信度 | high / medium / low（证据条数与一致性决定） |

## 3. 数据来源

- **造句/情境评分留痕**（SentenceLogs）：四维分数 + 错误标签，按词的场景归属聚合 → 场景维度与技能维度结论；
- **测评 FinalLevel 记录**（T-004 已存四维均值 + Top 错误标签 + 识别参考分）；
- **词掌握度**（UserWordRelationship + 词的场景标注）：各场景词覆盖率与回忆正确率；
- **阅读行为**（查词频率、文章难度）→ 阅读维度。

## 4. 生成与验证流程

1. **Profiler Agent**：测评完成后触发（之后 T-006 规划器接入前，这是唯一触发点；周级刷新留给 T-007）；调工具取上述数据 → 产出结构化 Finding 列表 → 持久化；
2. **Verifier Agent**：对每条 Finding **机械核查**——证据引用是否真实存在、引用的数值是否属实、样本量是否支撑置信度；不做主观改写。核查不通过的条目标记「存疑」，**不进入规划输入**（T-006 只消费已验证条目）；
3. **展示**：评估报告页从模板文案切换为已验证的 Finding 列表（存疑条目不展示或淡显标注）。

## 5. 验收标准（给周密）

1. 测评完成后自动生成 WeaknessProfile 并持久化，接口/页面可查；
2. 每条 Finding 带证据引用，引用可回溯到真实记录（SentenceLog/测评记录/词统计）；
3. Verifier 机械核查生效：篡改或伪造的证据会被标记「存疑」（测试构造坏证据验证）；
4. 展示层只呈现已验证条目；
5. 成本：Profiler+Verifier 每用户仅测评后运行一次，日级频次以下；
6. `dotnet test`、`npm run build` 通过。

## 6. 非目标

- Planner 消费画像（T-006）；瓶颈性质洞察与重规划（T-007）；
- 画像的多轮历史对比视图（后续迭代）。
