# 设计方案：画像冷启动「探索周」（T-024）

> 状态：已定稿（2026-07-30，顾言）
> 依据：report/sim-month/REPORT.md 发现三（首测 Finding 全灭 → 计划永远探索期 → 画像死锁）
> 前置：T-005 画像+Verifier、T-006 Planner、T-022 练习回写

## 1. 问题

首测后用户只有测评产生的几条 SentenceLog，LLM 每条 Finding 只引 1 条证据，Verifier 样本量纪律（medium≥2 / high≥3）把首测画像全灭 → Planner 只消费 Verified → 计划永远「探索期」兜底；画像重生成的唯一触发是瓶颈性质变化，而洞察对菜鸟不触发（T-025 另案）→ 死锁。仿真实测：30 天 5 份计划全部探索期，产品对用户的理解零增长。

## 2. 方案（顾言拍板）：把「探索期」从兜底文案变成有终点的旅程

### 2.1 探索周定义

注册起 7 天为探索周。期间 Planner 照旧生成周计划（覆盖率兜底不变），但**每天额外编排 1 个轻量场景表达任务**：从 taxonomy 轮转选子场景（优先词池已标注场景），出 1 道情境表达题（1-2 句话即可），走既有 free-expression 评分链路——目的就是攒证据，不是考试。

### 2.2 进度可见

Dashboard 计划卡在探索期不再只挂「探索期」徽章，显示：「探索周 第 x/7 天 · 再完成 N 次表达，生成你的专属画像」。N = max(0, 10 − 首测后产出证据条数)。

### 2.3 冷启动画像重生成（专用触发器）

满足任一条件即自动重生成画像（不等瓶颈触发，每用户仅一次，幂等）：

- 首测后满 7 天；或
- 首测后产出证据（SentenceLogs + FreeExpressionLogs）累计 ≥10 条。

挂在 ProfileScoreSnapshotWorker 日检里做条件判断，触发后走既有 `WeaknessProfileService.GenerateAsync(assessmentId: null)` + force Planner 链路。

### 2.4 Verifier 冷启动档

首份重生成画像（冷启动档）放宽置信纪律：**证据真实、数值一致但条数不足的 Finding，置信度降为 low 标 Verified 并注明「初步判断」**，不再整条 Questioned；low 置信 Finding 可进规划但前端画像展示带「初步」徽标。第二份画像起恢复既有纪律（不足即 Questioned）。证据伪造/越权/数值不符的机械核查任何情况都不放宽。

## 3. 约束

- 规则引擎分数权威不动：探索任务走既有评分与 T-022 回写，无新写入点；
- 成本：每用户冷启动仅多 1 次画像 LLM 调用 + 每日 1 次表达评分（用户本来就可能有练习，探索任务只是编排引导）；
- 探索任务跳过后补：当天不做不惩罚，证据计数按实际产出。

## 4. 验收标准

1. 新用户注册 → 跳过测评 → 7 天内每天只做探索任务：第 7 天画像自动重生成，≥1 条 Finding（含 low「初步判断」）进规划，新计划来源徽章变「个性化」；
2. 首测 Finding 全 Questioned 的用户，探索周攒够 10 条证据即触发重生成（不必等满 7 天）；
3. Dashboard 探索期文案含进度（第 x/7 天、还差 N 次）；
4. 第二份画像恢复既有 Verifier 纪律（人为构造证据不足 Finding 仍判 Questioned）；
5. 全链路幂等：重生成只发生一次，重复触发不产生第二份冷启动画像。
