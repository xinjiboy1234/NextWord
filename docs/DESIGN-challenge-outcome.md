# 设计方案：挑战「有结果化」（T-028）

> 状态：已定稿（2026-07-30，顾言）
> 依据：report/sim-month/REPORT.md 发现七（挑战过了也白过）
> 前置：T-022 练习回写、T-023 定级校准

## 1. 问题

仿真实测：4 次挑战（含 1 次通过 85 分）后分数、等级、徽章零变化，用户只得到「通过」二字；挑战全部按上一档（C1）出题但无解释；阅读单题 0/100 全有或全无，方差过大；历史记录「造句 3」无满分参照。挑战是升级的唯一通道，却是全产品反馈最弱的一环。

## 2. 方案（顾言拍板）

### 2.1 Daily 挑战通过即时有反馈

通过（非确认挑战）后：

- 结果页给一句即时画像点评（规则生成，零 LLM）：取本次三维得分与 Profile 三维分对比，「写作比你的当前水平高出一截，继续冲」/「阅读拖了后腿」之类，指出最长板与最短板；
- 发放徽章/计数：Profile 增加「挑战通过次数」与「首次通过 X 级」纪念标记（前端 LevelPanel 展示，复用既有等级历史区）；
- **不改分数**——分数权威仍只属于测评/确认挑战/练习回写，Daily 通过只给荣誉与解读。

### 2.2 升级候选强引导确认挑战

`IsUpgradeCandidate=true` 时：Dashboard 与挑战页顶部出现引导条「你已具备冲击 {下一级} 的实力，来确认挑战」；确认挑战通过按既有规则加分升级（不动）。LevelCheckWorker 每日刷新既有，无需改。

### 2.3 阅读题加量降方差

挑战包阅读题从 1 题增至 3 题（从库内按目标档选文出题，复用测评阅读题的选文与考点词口径），阅读得分 = 正确率映射（0/50/100 三档变 0/33/67/100 粒度），`lookupCount` 扣分口径不变。挑战阈值 `ReadingScoreMin:100` 相应下调为 67（配置，跟着题量走）。

### 2.4 挑战记录可读性

挑战页历史记录所有分数带满分参照（如「造句 3/5」「阅读 67/100」），AttemptedLevel 旁加一句解释「挑战比当前等级高一档的内容」。

## 3. 约束

- 规则引擎分数权威不动：确认挑战加分逻辑一行不改；
- 阅读题量增加的成本为零（题库内选文，无 LLM）；
- 徽章/计数从既有 ChallengeRecords 派生，不加新表（前端聚合或 profile 接口补字段，取实现简单者）。

## 4. 验收标准

1. Daily 挑战通过：结果页有最长/短板点评（与本次得分一致）、通过计数 +1；未通过无点评有鼓励文案；
2. IsUpgradeCandidate=true 用户 Dashboard 与挑战页均见确认挑战引导，点击发起的挑战带 confirmationChallenge=true；
3. 阅读 3 题：答对 2 题得分 67 可通过阈值；答对 1 题 33 不通过；ChallengeSession 结构兼容（旧会话数据不炸）；
4. 历史记录分数带满分参照、AttemptedLevel 有解释文案；
5. 既有挑战测试在新题量/阈值下全绿（预期随口径更新）。
